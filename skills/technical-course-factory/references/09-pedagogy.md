# 09 — Pedagogy

A course is not a list of facts. It is a sequence of experiences that change what the learner can do.

## Learning objectives

Write 3–5 objectives per lesson using observable verbs:

- Explain, identify, compare, implement, debug, refactor, design, evaluate.

Avoid:

- “Understand” without evidence.
- “Learn” without a task.
- “Know” without a test.

## Cognitive load

- One main idea per lesson.
- Introduce new terms gradually.
- Separate syntax from concept.
- Use worked examples before independent practice.
- Keep code snippets small.
- Remove irrelevant details.

## Worked examples

For each new concept:

1. Show a small example.
2. Explain the important line or decision.
3. Show the expected result.
4. Change one thing and ask what happens.
5. Give a similar exercise.

For beginners, err on the side of more examples. For advanced learners, use one realistic case and focus on tradeoffs.

## Retrieval practice

- Quiz at the end of every lesson.
- Mix recall, prediction and debugging.
- Ask “what happens if…?” not only definitions.
- Revisit previous concepts in later lessons.
- Use spaced review in module recaps.

## Misconceptions

Include 2–4 common mistakes per lesson:

- What the learner might think.
- Why it is wrong.
- How to detect it.
- How to fix it.

Beginner examples: indentation, types, scope, mutable defaults.
Intermediate: error handling, testing, abstractions.
Advanced: concurrency, performance, coupling.
Expert: operability, failure modes, organizational tradeoffs.

## Practice

- Guided: full steps, expected result.
- Independent: goal and constraints, no steps.
- Challenge: open-ended, multiple solutions.
- Project: integrates several lessons.

Practice should be realistic, small and testable. Avoid trivia and “write the syntax from memory” unless the goal is recall.

## Feedback

- Quizzes include answers and brief explanations.
- Exercises include acceptance criteria and a rubric.
- Code exercises can include sample tests or expected output.
- Solutions are optional and separate.

## Accessibility

- Clear headings.
- Short paragraphs.
- Tables for comparisons.
- Code labels.
- No images without alt text; prefer Mermaid.
- Define acronyms on first use.

## Lesson checklist

- [ ] Objectives are observable.
- [ ] One main idea.
- [ ] Worked example.
- [ ] Common mistakes.
- [ ] Guided practice.
- [ ] Independent practice.
- [ ] Quiz with answers.
- [ ] Key takeaways.
- [ ] Next step.
